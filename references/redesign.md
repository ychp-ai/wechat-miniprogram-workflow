# redesign · 页面重设计

## 输入与执行模式

输入可为已有页面/路径、设计目标、参考图或品牌规范。先读取页面及关联组件、样式、事件与数据来源；有预览能力时观察实际界面。没有截图时可以依据代码推进，但不能声称已看过效果。

- “只出设计/方案/原型”按指定形式交付，不修改业务实现。
- “重做页面/改版并落地”默认完成设计和代码实现，再验证。
- 仅说“重做页面设计”时先交付具体、可审阅的设计规范；用户已明确要求实现时直接落地，不重复索取设计确认。
- 未提供参考风格时依据产品、品牌与现有相邻页面制定一种明确方向；除非用户要求，不制作多套方案增加决策负担。

## 工作方法

1. 盘点旧页面合同：业务入口、操作事件、路由和分享参数、数据字段、权限判断、埋点、公共组件影响范围，以及加载、空、错误、禁用等状态。将要保留的能力与明确授权调整的交互区分开。
2. 定义重设计目标和页面信息顺序，产出具体的模块布局、内容与主次操作安排，以及配色、字号、间距、组件和状态规范。避免只用“高级感”等形容词代替可实施设计。
3. 按需使用 ui-ux-pro-max、frontend-design 或 impeccable。将建议适配当前小程序框架与渲染器，不照搬 Web API，不默认迁移 Skyline 或重建工程。
4. 实现模式下替换指定页面的呈现层，保留数据绑定和业务行为。需要改变共享样式或组件时检查实际调用方，避免相邻页面被连带改版。无授权不删除功能、改接口合同或替换真实数据为模拟数据。
5. 检查不同内容长度、主要状态、目标屏幕、安全区域和键盘/滚动行为，验证旧操作入口仍能工作。将视觉观察与功能回归分开记录；使用实际可用预览，做一次集中检查与修复，必要时一次确认，不无限打磨。

## 交付

输出 page-redesign.md 或已有设计文档：改版目标、新布局及规范、旧能力到新位置的对应关系、状态设计；实现模式同时交付页面代码和实际验证结果。缺失素材和未验证设备明确列出。不自动改版其他页面或上传发布。
